페이지 파일은 GitHub/GitHub Pages에서 실행할 수 있지만, 작업 데이터는 서버나 GitHub로 전송하지 않고 현재 브라우저의 LocalStorage에만 저장합니다. 같은 PC·같은 브라우저에서 기록이 유지되며, 브라우저 데이터 삭제 또는 PC 변경 시 사라질 수 있으므로 정기적으로 JSON 백업을 권장합니다.
🏢 기본 설정
⚠ 초기화
현재 진행중 작업과 저장된 일보/기준정보를 모두 삭제합니다. 필요하면 먼저 JSON 백업을 내려받으세요.
❔ 가공 생산일보 사용안내

이 페이지는 GitHub/GitHub Pages에서 열어 사용할 수 있습니다. 생산일보·진행작업·기준정보는 GitHub에 저장되지 않고, 사용 중인 PC의 현재 브라우저 LocalStorage에만 저장됩니다.

🔁 기본 작업 흐름 위에서 아래 순서대로
1

기준정보를 먼저 등록

처음 사용할 때 메뉴의 기준정보에서 설비코드/설비명과 품번/품명/공정/기준 CT를 등록합니다. 한 품번에 공정이 여러 개면 공정별로 각각 등록하세요.

2

작업 기본정보 입력

작업입력에서 작업일자, 작업자, 설비, 작업지시번호, 품번, 공정, 계획수량, 소재 LOT 등을 입력합니다. 품번과 공정을 기준정보에서 선택하면 품명과 기준 CT가 자동 적용됩니다. 입력 내용은 가동 전에도 임시저장됩니다.

3

가동 시작

실제 설비 작업을 시작할 때 ▶ 가동 시작을 누릅니다. 이 시점부터 순가동 시간이 계산됩니다.

4

작업 중 정지 발생

공구교환, 치수측정, 소재대기, 설비이상 등이 발생하면 ⏸ 정지 시작을 누르고 정지 사유를 선택합니다. 다시 생산을 시작할 때 ▶ 정지 해제를 누르면 정지시간과 순가동시간이 분리 기록됩니다.

5

수량과 불량 입력

작업 중 또는 종료 전에 양품수량·불량수량을 입력합니다. 불량이 있으면 불량유형을 선택하고 필요한 상세내용은 특이사항에 적습니다. 화면에서 달성률·가동률·성능률을 확인할 수 있습니다.

6

작업 완료로 시간 확정

실제 가공이 끝났을 때 🏁 작업 완료를 누릅니다. 순가동 및 정지시간이 이 시점에서 확정됩니다. 수량과 내용을 한 번 확인하세요.

7

생산일보 저장

💾 현재 작업을 생산일보로 저장을 누르면 해당 작업이 일보 / 이력에 등록됩니다. 저장 위치는 서버가 아니라 현재 브라우저의 LocalStorage입니다.

8

일보 확인·수정·CSV 출력

일보 / 이력에서 일자/설비별 기록을 확인하고, 잘못 입력한 내용은 수정할 수 있습니다. 정지내역과 수정이력도 확인할 수 있으며 필요하면 CSV로 다운로드합니다.

9

정기 백업

설정 / 백업에서 전체 백업(JSON)을 내려받아 보관하세요. PC 교체, 브라우저 데이터 삭제 등에 대비한 원본 백업입니다. 다른 PC에서 사용할 때는 백업 복원으로 데이터를 옮길 수 있습니다.

⚠ 꼭 알아둘 점
GitHub에 올라가는 것은 프로그램 HTML 파일입니다.
작업자가 입력한 생산 데이터는 GitHub 저장소나 서버로 자동 업로드되지 않습니다. 같은 URL을 여러 PC에서 열어도 각 PC/브라우저마다 데이터가 따로 저장됩니다.
브라우저를 닫았다 다시 열었을 때 진행 중 작업이 감지되면
실제 설비가 계속 돌아갔다면 가동으로 유지, 설비가 멈춰 있었다면 정지로 처리를 선택하세요.
운영 초기 권장 순서
기준정보 등록 → 시험 작업 1건 → 정지/재가동 시험 → 일보 저장 → 수정 시험 → JSON 백업/복원 시험 후 실제 생산에 적용하는 것이 좋습니다.
